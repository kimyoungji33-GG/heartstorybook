## 이번 변경 — 승인된 선택형 시안

[정의서와의 차이](docs/requirements-gap.md)를 먼저 확인하세요. [최신 정의서 1.1 사본](docs/reference-requirements-2026-10-16.md)(공개 기준 `504e343`)과 비교했습니다. 사본의 원문은 변경하지 않았습니다.

- 기존 책장·원문·그림·녹음·독서 주소를 보존했습니다. 새 시안은 대문이나 기존 메뉴에 연결하지 않았습니다.
- `/pilot/`에 『작은 손에 담긴 따뜻한 빵』의 상황을 바탕으로 별도로 쓴 선택형 글 시안을 추가했습니다. 원작의 대체 원고가 아닙니다.
- 지우·준호·빵집 주인 세 역할, 역할마다 두 번의 두 갈래 선택으로 총 **12개 경로와 12개 결말**을 제공합니다. 정답·점수·실패 판정은 없습니다.
- 각 선택에는 관찰 단서, 선택한 말·행동, 직후 반응, 다음 장면 ID가 있습니다. 두 선택의 조합이 결말로 연결됩니다. 반응은 아래 기록에 누적됩니다.
- 새 선택 장면에 맞는 그림과 직접 녹음은 아직 없습니다. 원작 그림·녹음을 자동 재사용하지 않습니다. 기존 독서 화면에서 원작을 계속 볼 수 있습니다.
- 시안의 영어·스페인어는 외부 원어민 감수 전 초안입니다. 번역이 빠지면 해당 부분에 **준비 중 / Coming soon / Próximamente**를 표시하며 한국어로 몰래 대체하지 않습니다.
- 2026-10-16 사용자가 어른 동화와 앞서 승인한 내용의 GitHub 반영을 요청했습니다. 반영하면 `/pilot/`도 직접 주소와 저장소에서 공개된다는 점은 동일합니다.

## 실행

Node.js가 설치된 컴퓨터에서 이 저장소 폴더를 VS Code로 열고 터미널에서 실행합니다. 외부 라이브러리 설치나 `npm install`은 필요 없습니다.

```powershell
node pilot/serve.mjs
```

브라우저에서 <http://localhost:4176/pilot/>를 여세요. 기존 대문은 <http://localhost:4176/index.html>입니다. 종료는 터미널에서 `Ctrl+C`입니다. 포트가 사용 중이면 이전 미리보기 서버를 종료하세요.

파일을 직접 더블클릭하는 방식은 시안의 모듈 불러오기에 맞지 않습니다. 위 로컬 서버를 사용하세요. 서버는 내 컴퓨터의 `127.0.0.1`에서만 접속을 받습니다.

## 자료 수정

| 파일 | 용도 |
|---|---|
| `pilot/data.js` | 새 선택 이야기·세 언어·역할·단서·반응·결말 |
| `pilot/engine.js` | 경로 이동·URL 저장/복원·누락 번역 처리 |
| `pilot/app.js` | 화면·세 언어 공통 안내·선택 기록 |
| `pilot/style.css` | 반응형 화면·버튼·글자 크기 |
| `pilot/tests.mjs` | 경로·번역·상태·기존 파일 보존 검사 |
| `pilot/original-files.json` | 변경 전 기존 추적 파일 SHA-256 목록(README 제외) |
| `pilot/approved-changes.json` | 책 제외·어른 책 개편·공통 표시 등 승인된 후속 변경의 해시와 이유. 최초 보존 기준은 유지 |

1. `data.js`의 `roleDrafts`에서 문장을 수정합니다. `t(한국어, 영어, 스페인어)` 순서입니다. 누락 언어는 `null`로 두면 준비 중이 표시됩니다. 빈 문자열도 누락입니다.
2. `opening`은 시작 상황, `clues` 두 개는 각 단계의 단서입니다. `prompts`는 첫 질문과 첫 선택에 따라 달라지는 두 번째 상황입니다.
3. `labels`와 `reactions`의 앞 두 개는 첫 선택 a/b, 뒤 두 개는 두 번째 선택 a/b입니다. 첫 반응을 기록에 유지하고 두 번째 상황을 다르게 연결합니다.
4. `ends` 순서는 **aa, ab, ba, bb**입니다. 결말은 그 경로에서 실제로 한 행동과 일치해야 합니다.
5. 아래 생성 부분이 역할마다 `start → follow-a/b → end-aa/ab/ba/bb` 그래프를 만듭니다. 각 선택의 `next`, `clueId`, `reaction`과 결말의 `route`를 검사합니다.
6. 공개 후 책·역할·장면·선택 ID는 번역하거나 함부로 변경하지 마세요. 저장된 링크가 이 ID를 사용합니다. 구조를 바꾸려면 이전 주소의 이동 규칙과 검사를 함께 바꿉니다.

아이 책의 기존 `six-books-data.js`, `book-locales.js` 원문은 보존합니다. 어른 책 개편은 별도 자료와 승인된 공통 책장·독서 화면 변경으로 적용합니다. 누락 처리는 사용자 보호 장치이며, 공개 전에는 번역을 완성합니다. 검사를 통과시키기 위해 누락 검사를 지우지 마세요.

## 상태와 개인정보

주소에 `book`, `role`, `scene`, `lang`, 반복된 `choice`가 저장됩니다. 예:

```text
/pilot/?book=errand&role=junho&scene=end-ab&lang=es&choice=a&choice=b
```

언어 전환·새로고침 후 같은 책·역할·장면·선택을 복원합니다. 브라우저 뒤로/앞으로 가기도 지원합니다. 역할을 직접 바꾸거나 처음부터 버튼을 누르면 선택을 새로 시작합니다. 잘못된 주소는 안내와 함께 유효한 상태로 정리합니다.

시안은 선택 기록을 서버나 데이터베이스에 저장하지 않습니다. 주소를 공유하면 선택 경로도 공유됩니다. 주소에 이름·개인 사연·비밀을 넣지 마세요. 접속 서비스나 호스팅 서버의 일반 접근 기록은 별개입니다. 기존 사이트의 언어 설정 저장 동작은 그대로입니다.

## 검사

저장소 폴더에서:

```powershell
node --test pilot/tests.mjs
git diff --check
git diff --stat
git status --short
```

자동 검사는 12개 경로 전체의 두 번 선택·결말 도달, 막힌 연결·순환·도달하지 않는 장면, 단서와 반응 연결, 세 언어 문장 누락, 언어 전환·새로고침의 상태 보존, 잘못된 주소, 누락 번역의 원문 대체 금지, 기존 추적 파일 보존을 확인합니다. 보존 목록은 작업 이전 기준입니다. 변경을 숨기기 위해 재생성하지 마세요. 추후 승인된 원문 변경 시 별도 변경 기록과 함께 갱신합니다.

브라우저 수동 검토:

1. 세 역할에서 aa·ab·ba·bb를 각각 선택하고 결말·반응의 의미를 읽습니다.
2. 첫 선택 뒤와 결말에서 한국어→English→Español로 바꾸고 새로고침합니다. 인물과 선택이 같아야 합니다.
3. 한 선택 되돌리기, 처음부터, 브라우저 뒤로/앞으로를 확인합니다.
4. 임시 자료 사본에서 번역 하나를 `null`로 바꾸고 준비 중 표시를 확인합니다. 원본으로 되돌리고 다시 검사합니다.
5. 휴대전화·큰 화면에서 줄바꿈·버튼·키보드 조작을 확인합니다. 자동 검사만으로 문학적 완성도나 번역 자연스러움까지 보증하지는 않습니다.

## 공개 운영

현재 공개 사이트는 GitHub Pages의 정적 사이트입니다. 이번 변경에는 승인된 어른 책 네 권과 별도 선택형 시안이 포함됩니다. **메뉴에 연결하지 않아도 파일을 푸시하면 직접 주소로 공개될 수 있습니다.**

검토·승인 후에만 다음 순서로 진행합니다.

1. 이 문서·차이 문서·`git diff`와 새 파일을 검토합니다. 기존 책장·원문 보존을 확인합니다.
2. 세 언어 문장·분기 의미·접근성·모바일 화면과 테스트를 확인합니다. 승인한 자료만 준비합니다.
3. `git remote -v`, 현재 브랜치, GitHub Pages의 배포 대상 설정을 확인합니다. 비밀·검토 전 자료를 제외합니다.
4. 승인한 파일만 커밋하고 해당 공개 저장소의 배포 브랜치로 푸시합니다. 실제 저장소 설정에 맞게 Pages 완료를 확인합니다. 2026-10-16 사용자 요청에 따라 이번 변경에 이 단계를 실행합니다.
5. 공개 주소에서 12개 경로와 언어 전환을 재확인합니다. 오류가 있으면 문제 커밋을 되돌리고 재배포합니다.

## 비공개 운영

- 개인 검토는 로컬 서버를 쓰고 외부 공유·포트 개방·공개 푸시를 하지 않습니다.
- 여러 사람이 비공개 검토하려면 인증과 접근 제어가 있는 별도 호스팅을 사용합니다. 승인 사용자만 HTML·자료·이미지의 **각 요청**을 받을 수 있어야 합니다. 로그인 화면만 붙이고 자료 주소를 공개하면 보호되지 않습니다.
- 비공개 저장소라고 배포 사이트도 자동으로 비공개가 되는 것은 아닙니다. Pages의 공개 범위를 별도로 확인하세요. 확인할 수 없으면 비공개 원고를 배포하지 않습니다.
- 숨긴 메뉴·주소·robots/noindex·브라우저 자바스크립트의 비밀번호는 접근 제어가 아닙니다. 공개 자료와 비공개 원고를 별도 저장소·배포 대상으로 분리합니다.
- 계정·서버 저장·인증 기능은 이번 시안에 구현하지 않았습니다. 이 문단은 비공개 운영 시 필요한 조건을 설명합니다.
